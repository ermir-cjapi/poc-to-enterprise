PART 1 — Q&A

Symptom → Pillar

HR employee retrieves IT’s server-access runbook via NovaAssist. Root cause?

Hint: which pillar is about who is allowed to see which data?

? 1 min  |  Quiz: HR retrieves IT runbook

? Correct: Data & Governance (Pillar 1) � no dept_id namespace in the vector DB.

Common wrong answer: Security. Here is the distinction:
 � Security failure = unauthenticated user accessing the system.
 � Data & Governance failure = authenticated, logged-in user seeing the wrong tenant's data.
Auth was working fine. The isolation layer was missing entirely. That is Pillar 1, not Pillar 2.

The fix:
Every chunk tagged dept_id at ingest.
Every retrieval query filters on the JWT dept claim.
Without this, one wrong call exposes everything.

HR: "Did quality drop after Alex changed the system prompt last Tuesday?" No data exists. Which gap?

Interview talking point
"We gate every prompt change on a 50-question golden set; faithfulness must stay >0.85 before deploy" says more than "we use RAG."

? 1 min  |  Quiz: quality dropped after prompt change

? Correct: Observability (Pillar 4) � no offline eval set, no production feedback loop.

Common wrong answer: Reliability. Key distinction:
 � Reliability = the system stays up.
 � Observability = you can measure quality, cost, and latency.

Say:
"Before changing any prompt in production, you need a test set of known questions and expected answers.
Run it in CI. If faithfulness drops, the deploy is blocked.
Observability for RAG is not just logs � it is an eval pipeline."

Interview differentiator (say out loud):
"We gate every prompt change on a 50-question golden set;
faithfulness must stay above 0.85 before deploy."

NovaAssist OpenAI key scraped from public GitHub repo. First mitigation?

? 1 min  |  Quiz: API key scraped from GitHub

? Correct: Security (Pillar 2) � rotate key immediately + Key Vault + secret scanner in CI.

Step 1 (immediate): Rotate the key AND assume malicious use during the hours it was exposed.

Step 2 (permanent fix): Key Vault + managed identity. Never commit secrets again.

? Never suggest: ".env in a private repo" � the .env file is exactly the problem.

Why not fine-tuning?
Fine-tuning bakes knowledge into frozen weights.

RAG externalises knowledge into a vector store updated in real time � update a PDF today, model answers correctly today.

Fine-tuning = teach the model a new skill.
RAG = give the model a library to look things up in.
NovaAssist needs a library that updates on Mondays � not a skill.
