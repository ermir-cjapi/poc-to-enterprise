Core message
Enterprise architecture is not a checklist you memorise. Some of it is designed upfront — before a single user touches the system. The rest is refined under pressure, when real failures reveal what you missed. Both matter. Today we practise both.
Pause on each metric. Different stakeholders see different problems: HR = wrong answer, Security = leak, CFO = cost. Enterprise needs to address all simultaneously.

Who Cares About What?

HR sponsor

"One wrong parental-leave answer is a reputational crisis. Every answer must cite its source."

IT Security

"Finance docs must never surface in HR queries. Log every retrieval, 90-day retention."

CFO

"Cap AI spend at $2K/month until we prove ROI. I don't care about GPUs — I care about the bill."

Platform team

"Build a pattern we can reuse for the next 5 AI features, not a one-off script Alex maintains."
Architecture meetings are stakeholder trade-off sessions, not technology debates. Write down what each person optimises for — you design differently for each.

PART 0 — WAR ROOM

You Are Alex’s On-Call Engineer — 2:14 AM

Step 1 of 3

OpenAI dashboard: $1,400 in 48 hours, still climbing. You get paged. What do you do right now?

✓ Key revoked in 3 min. Bill stops at $1,700. 12 users get a 503 — on-call #2 opens war-room Slack thread.
Step 2 of 3 — 2:19 AM

Service is down but spend is stopped. A new key is issued. How do you redeploy?

⚠ Rate limited. Spend slows but key stays live. 4 h later: $2,900. Finance pings at 6 AM.
Step 2 of 3 — 6:00 AM

Security DMs you: the shared key appears in a GitHub commit from 3 weeks ago — repo was briefly public. What now?

✗ Ignored. By 8 AM the bill is $4,200. Finance cancels the card. All 120 users are down. CFO schedules a post-mortem for 5 PM.
Step 2 of 3 — 8:02 AM

Post-mortem starts. CFO asks: “What were the root causes?” What do you list?

✓ Bill: $1,700. Key in vault. Budget alert live. Re-embed fixed next morning. CFO signs off v1.0 budget.
Enterprise pattern: Revoke → Isolate → Alert → Document. An automated cost alert at 80% budget would have caught this at $100, not $1,400.
⚠ Bill: ~$2,900. Key rotated but .env habit persists. One more git push will repeat this. CFO approves v1.0 with conditions.
The fix that solves the symptom ≠ the fix that prevents recurrence. Key Vault + CI pre-commit scanner is the permanent fix.
⚠ Correct root causes. CFO is satisfied with the analysis. But none of it is fixed yet — this only buys trust for 48 h.
Good post-mortem analysis; bad runtime response. Enterprise = automated alerts + immediate revocation protocol. You named the problem; now build the system that prevents the 2 AM page.
✗ CFO is not satisfied. Prices did not change. This was entirely preventable with a $2K/month budget alert and async ingestion. v1.0 budget denied.
Never blame the vendor for your architecture gaps. No rate limit + sync embed + shared key = this exact failure mode. Write the ADR before v1.0.
Don't reveal the correct path. Let students choose. After an outcome: "What automated system would have caught this at 2 AM?" (cost alert at 80% threshold + Key Vault). Then: "Let's name the 6 pillars that explain why this happened."

NovaAssist Enterprise Checklist

  • Dept namespace on every vector query (Milvus / Qdrant)
  • JWT with dept_id claim — mandatory on every request
  • Secrets in Key Vault — never in git or .env
  • Citation required in every RAG answer (guardrail)
  • Async ingestion worker — never embed inside HTTP handler
  • Reranker tuned against golden eval set before deploy
  • 30-Q offline eval in CI (faithfulness gate)
  • Online: thumbs-down, retrieval drift, $/query
  • Agent: max_steps=8, timeout, cost cap per session
  • Policy engine: auto / gate / block per tool
  • Human approval on every write/irreversible tool
  • Idempotency key on create_ticket and all write tools
  • Model router: Llama-8B NIM for FAQ, cloud LLM for reasoning
  • FAQ embedding cache (top-200 queries)
  • Monthly cost cap with alert at 80%
  • Architecture diagram + NFRs + ADR links in README
