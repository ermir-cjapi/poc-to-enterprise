Core message
Enterprise architecture is not a checklist you memorise — it is a sequence of decisions triggered by real failures and stakeholder pressure.
Pause on each metric. Different stakeholders see different problems: HR = wrong answer, Security = leak, CFO = cost. Enterprise needs to address all simultaneously.

Who Cares About What?

HR sponsor

"One wrong parental-leave answer is a reputational crisis. Every answer must cite its source."

IT Security

"Finance docs must never surface in HR queries. Log every retrieval, 90-day retention."

CFO

"Cap AI spend at $2K/month until we prove ROI. I don't care about GPUs — I care about the bill."

Platform team

"Build a pattern we can reuse for the next 5 AI features, not a one-off script Alex maintains."
Architecture meetings are stakeholder trade-off sessions, not technology debates. Write down what each person optimises for — you design differently for each.

NovaAssist Enterprise Checklist

  • Dept namespace on every vector query (Milvus / Qdrant)
  • JWT with dept_id claim — mandatory on every request
  • Secrets in Key Vault — never in git or .env
  • Citation required in every RAG answer (guardrail)
  • Async ingestion worker — never embed inside HTTP handler
  • Reranker tuned against golden eval set before deploy
  • 30-Q offline eval in CI (faithfulness gate)
  • Online: thumbs-down, retrieval drift, $/query
  • Agent: max_steps=8, timeout, cost cap per session
  • Policy engine: auto / gate / block per tool
  • Human approval on every write/irreversible tool
  • Idempotency key on create_ticket and all write tools
  • Model router: Llama-8B NIM for FAQ, cloud LLM for reasoning
  • FAQ embedding cache (top-200 queries)
  • Monthly cost cap with alert at 80%
  • Architecture diagram + NFRs + ADR links in README
